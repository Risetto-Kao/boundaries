# 多語言支援

支援繁體中文（`zh-Hant`）、英文（`en`）、日文（`ja`）、韓文（`ko`）。
導覽列的語言選單適用於所有頁面；選擇會存入一年有效的 `boundaries-locale`
cookie。首次使用依瀏覽器的 `Accept-Language` 選擇支援的語言，否則使用繁體中文。
既有問卷 URL 不變，分享連結的接收者可自行選擇語言。

介面描述、建立與填答提示、答案標籤、結果、帳號、載入狀態、錯誤、日期和網站
metadata 使用同一組翻譯。語言切換透過 React context 和 `router.refresh()`
更新頁面，保留正在輸入的內容和作答進度。

問卷標題、說明、題目、暱稱可輸入英文、日文、韓文及混合文字，保存與顯示原文，
不做自動翻譯。答案在資料庫和 API 中繼續使用 `yes` / `no` / `depends`，只有顯示
標籤隨語言改變。不需要修改資料庫或執行 migration。

## 新增語言

1. 複製 `frontend/lib/i18n/messages/en.ts` 為新語言檔案並翻譯全部訊息，保留
   `{count}`、`{title}` 等插值名稱。檔案以 `satisfies Messages` 檢查鍵值完整性。
2. 在 `frontend/lib/i18n/config.ts` 的 `languages` 登錄 BCP 47 語言代碼、原文名稱、
   日期 locale 和訊息檔案。`Locale` 型別、選單及瀏覽器語言比對會自動擴充。
3. 若同一語言有多個地區變體，先比對完整代碼，再以主要語言匹配；registry 中的
   順序決定沒有精確匹配時的預設地區變體。
4. 執行 `pnpm --dir frontend test:i18n`、`lint`、`typecheck`、`build`，並查看新增
   語言的手機和桌面版面。

新增介面文字時，先在 `zh-Hant.ts` 加入有意義的 key，再補齊所有翻譯。
Client Component 使用 `useI18n()`；Server Component 使用 `await getI18n()`。
API 使用 `getRequestI18n(request)`，優先順序為有效的 `X-Boundaries-Locale`、
cookie、`Accept-Language`。建立與填答表單會送出目前選擇的語言。
驗證使用每個請求獨立的 `createValidationSchemas(locale)`，避免不同使用者
的語言互相影響；所有字串保持 Unicode，並修剪頭尾空白。

## 驗證範圍

`test:i18n` 驗證語言協商、翻譯完整性及插值、多語輸入、空白與長度限制、
驗證語言隔離及穩定答案值。CI 執行此檢查。

本次雲端驗證使用 Node 24.21.0 / pnpm 10.13.1。Chromium 390px 手機尺寸檢查
四種語言的建立頁，確認切換後輸入保持、cookie 保持、沒有橫向溢出；以暫存
fixture 檢查實際填答／結果元件的語言切換、暱稱、進度及答案值。建立與提交的
成功寫入使用攔截請求檢查 payload，沒有連線到真實資料庫。另對本機 API 發送
無效輸入，確認英文、日文、韓文的驗證錯誤。fixture 已移除。另以 1280px 桌面尺寸檢查首頁、建立、登入、安裝及 404 頁，
確認 metadata／manifest 語言，並檢查 malformed JSON、來源與問卷 ID 的多語錯誤。

未驗證真實資料庫寫入、Google OAuth、Arc 或 iPhone Safari；這些需使用隔離
開發資料庫與對應裝置。不得為了驗證對正式資料庫寫入資料。
