# 設計差異與待決定項目

依 `Boundaries Design Spec.md` 及 `design/Boundaries Visual Direction/` 比對。這次沒有變更 Prisma／SQL 資料模型，也沒有對正式資料庫進行驗證寫入。

| 畫面 | 項目 | 原因 | 建議做法 |
| --- | --- | --- | --- |
| 建立／編輯、列表 | 類別欄位、最多三個標籤、四語類別名稱、類別 OR 篩選與類別搜尋（§9.3、§9.5） | 現有 Survey 沒有類別欄位；完整實作涉及持久化、既有資料與正式資料庫部署。這次跳過類別整組功能，不用示範資料假裝已有類別。 | 後續依 §9 新增類別欄位及驗證，準備隔離環境 migration、舊資料回填與正式部署方案，再補標籤和篩選。 |
| 列表、建立／編輯 | 持久化語言欄位與建立當下介面語言 fallback（§8、§9.4） | 已補內容字形偵測、四語標籤與單選篩選；未新增資料欄位，因此無法保存建立當下介面語言。純漢字日文、混合語言與只有符號的內容無法可靠分類。 | 新增語言欄位，建立時以介面語言作 fallback，編輯時重新偵測；既有資料批次回填。不確定內容應決定分類政策。 |
| 列表 | 「我的邊界」與現有公開列表的範圍衝突 | 規格稱這頁只列本人建立的；目前首頁與列表列出全部邊界。依「保留現有功能」維持公開列表，編輯入口只對登入擁有者顯示。 | 決定首頁是否改為私人列表，以及訪客／無擁有者舊資料要如何呈現或認領；不應以持有公開連結作為編輯權限。 |
| 編輯／刪除 | 訪客及無擁有者舊邊界無法管理 | 新功能使用既有 ownerId 與帳號開關，不替訪客創造不安全的所有權。擁有者可修改標題、描述、題目、排序並刪除整份。 | 先決定訪客所有權及舊資料認領方案。登入流程仍沿用現有功能。 |
| 編輯、結果 | 已有答案時修改題意、刪題的歷史語意 | 保留題目 ID 可避免重新排序讓答案錯位；刪除題目依現有 Cascade 一併移除該題答案。規格允許編輯，但沒有定義歷史版本。 | 決定是否在已有答案後限制修改／刪題，或另做題目版本與歷史答案保留；後者需要後端與資料模型擴充。 |
| 填答 | 空暱稱（§9.10） | 規格尚未決定；維持現有訪客必填、登入使用者以現有帳號名稱 fallback 的行為。 | 決定是否允許匿名及如何避免重名，另案處理。 |
| 填答、資料 | maybe 與現有 depends 值衝突 | 規格資料值寫 maybe，現有驗證與儲存使用 depends。三態顯示、黃底與三角形已符合畫面，不改既有資料。 | 維持 depends；若要更名，另準備 API 相容與資料移轉。 |
| 填答 | 極長題目與固定 320px 牌卡 | 現有題目不限制字數。一般牌卡高 320px；長文字必要時增高，避免截掉內容，也不自行增加字數限制。 | 決定題目字數上限、縮字或卡片內捲動設計；目前優先完整呈現既有內容。 |
| 全域 | 登入／訪客流程、設定頁、介面語言下拉、無效連結、載入／錯誤、深色模式、列表排序 | §9 明列尚未設計。沿用現有行為與文案，共用 tokens 與控制項樣式隨本次更新；列表保留建立時間由新到舊。 | 提供這些畫面的規格後另案比對；沒有新增說明文案或發明新流程。 |

## 已補的 §9 功能

- §9.1–2：有擁有者權限的編輯、儲存與整份刪除；題目拖曳、鍵盤排序、新增、立即刪除、空白題忽略、20 題上限及儲存 toast。
- §9.4–5：不變更模型的內容語言偵測、語言篩選，以及標題／語言名稱搜尋。
- §9.6、8：矩陣／清單切換、依公式計算分歧底色、三人以上精簡矩陣與卡片內捲動。
- §9.7：邀請浮層／手機 bottom sheet、真實連結複製、Web Share 支援偵測、真實 QR、Esc／焦點限制。
- §9.9：Pointer Events 左右滑、雙擊看狀況、三態按鈕、表態進度條、重新開始與直接進入結果。

## 驗證範圍與限制

- 全部建立與填答資料都在本機隔離 PostgreSQL，沒有正式／Preview 資料寫入。
- Arc 電腦寬度完成建立 → 填答 → 結果，檢查結果及邀請視窗。Arc 裝置模擬的輸入／點擊不穩定，390×844 主流程改用內建瀏覽器補驗；這不是實機 iPhone Safari 驗證。
- 390px 檢查列表、建立、填答、矩陣、清單、邀請；四語切換 lang／字體順序與頁寬均正確。題目指標拖曳、鍵盤排序、刪除、雙擊、左右滑、未達門檻彈回、重新開始、搜尋及語言篩選已操作。
- 2 人：不同答案 score=.75／底色 alpha=.20；一致白底。6 人：4:2=.5、3:3=.75、5:1=.25、2:2:2=1、一致=0，計算與實際結果列吻合。
- PATCH／DELETE 使用本機隔離資料庫及 mock 身分驗證處理器：訪客／非擁有者／外部 Origin 被拒、擁有者可儲存／增刪排序、舊 revision 回 409、刪題及整份刪除符合既有 cascade。沒有完成真實 Supabase 登入後的編輯頁端到端驗證。
- QR 編碼實際邀請 URL；Web Share 顯示條件已檢查，未操作實機系統分享選單。

- 本機 lint、typecheck、build 均通過；auth 9 項、i18n 5 項、design 2 項單元測試通過。這些程式檢查不代替 UI 主流程操作。
- 本次 Preview 分支已透過 Vercel 既有登入設定 localhost 連線占位值，正式環境連線沒有更動；因此 Preview 僅供靜態檢查，完整主流程驗證使用本機隔離資料庫。
