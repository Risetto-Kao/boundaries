# Boundaries — Phase 1 設計盤點、Phase 2 視覺探索

日期：2026-10-09。此文件是設計草案，不是品牌定案或正式 Design System。

## 本次範圍

閱讀實際 app routes、產品元件、共用 UI、全域樣式、驗證規則、API、資料模型、登入與個人歷史機制，以及產品與開發文件。以實作為現況依據；舊 PRD 與架構文件只提供脈絡，不代表功能已存在。

正式產品原始碼未修改。原型位於 `design/phase-1-2/`，是獨立的 HTML/CSS/JavaScript，不加入 Next.js routes、正式導覽、建置或資料庫。保留現有 Next.js 16、React 19、Tailwind 4、shadcn/Radix 與 Lucide 技術方向；之後定案再映射到現有元件。

## 2. 主要 User Flow

**建立者：** 首頁 → 建立問卷 → 輸入標題／描述／題目 → 建立成功 → 開啟填寫頁 → 複製連結 → 邀請他人。

**參與者：** 直接進入分享連結 → 可保持訪客或先登入 → 輸入暱稱 → 右滑 Yes／左滑 No／雙擊 Depends，也可用按鈕 → 可用上一題修改 → 全部作答後提交 → 結果矩陣 → 邀請下一位。

**回訪：** 首頁／舊列表找到表單 → 填答或結果；登入者另可從 `/account` 查看自己建立和填寫的紀錄。

訪客資料仍保留在共用表單，但不成為個人帳號歷史；登入後不會自動認領先前的訪客紀錄。同一問卷暱稱不可重複，由資料庫唯一約束與 API 409 處理，並非 README 所描述的 localStorage 身分鎖定。

## 4. 設計問題與保留重點

| 觀察與依據 | 影響 | 本次探索方式 |
| --- | --- | --- |
| `AccountNav` 與 `FormPortal` 各有 Boundaries 品牌列；Arc 首頁已確認重複 | 增加垂直高度，主動作被導覽分散 | 合併視覺層級為一列，保留訪客與登入入口；此為原型呈現，不改正式架構 |
| 首頁主按鈕 blue-700、帳號登入 slate-900、共用 Button 中性 primary | 相同重要性沒有一致的視覺規則 | 每方向固定一個品牌主動作色，No／Yes 語意另管 |
| 首頁大字／入口卡與內頁 CardTitle 尺度不同 | 像數個不同時期的表單頁，缺乏整體語言 | 每方向共用標題、正文、輔助文字與規則線 |
| 外層 Card、題目容器、輸入框、題卡反覆套框 | 全頁視覺重量偏向容器，核心題目被稀釋 | A 用紙色＋細線，B 只保留必要柔和表面，C 用刊物規則線 |
| 題卡 28px／shadow-lg 與其他頁面不一致 | 填答像另一套產品，堆疊動作帶入遊戲感 | 保留單題與手勢，探索更安靜的題卡，不把視覺動畫當新功能 |
| 語言交替用「表單／問卷」、「Depends／看狀況」，技術說明多 | 使用者需要自行解讀；品牌敘事仍偏收集與衝突 | 原型保留實際產品文案與答案值；詞彙一致與敘事調整列為後續討論 |
| `TableCell` 全域 whitespace-nowrap，問題欄僅 min-w-64 | 長題目和多人矩陣在手機容易變成很寬的表格 | 原型題目允許換行，人員欄保持可讀寬度，只讓表格橫向捲動 |
| 共用 Button h-9=36px／sm=32px，而首頁 44px、作答 56px | 手機控制項的有效點按區域不一致 | 原型主要操作 ≥44px；正式導入再統一 hit area |
| 多處輔助文字用 slate-400，部分錯誤只有紅色文字且未連結欄位 | 對比與錯誤定位需要更完整的檢查 | 原型使用較深輔助色、可見 focus、文字＋圖示辨認回答，並保留進度可存取資訊 |

值得保留：入口清楚、暱稱降低參與門檻、三種答案簡單、手勢有按鈕替代、上一題允許修正、結果矩陣直接比較、載入與空白狀態已有基礎。

品牌上的重要取捨：沿用「旅遊絕交問卷」是為了公平比較既有內容，不代表建議將「絕交／衝突／誰跟誰合不來」作為未來品牌主敘事。新背景更重視理解差異，Phase 3 可在方向選定後討論語氣；目前未採用新標語或新 Logo。

## 5. 三方向比較

| | A 紙感編輯 | B 清晰人文 | C 緊湊刊物 |
| --- | --- | --- | --- |
| 概念 | 可一起填寫的生活刊物 | 清楚、舒服的日常對話 | 觀點與差異的清晰索引 |
| 背景／文字／主動作 | #F5F1E9／#282620／#97442F | #FAFBF8／#25372F／#35634B | #F7F8FB／#202B42／#304E8A |
| 中文標題 | Songti TC，後續候選 Noto Serif TC | PingFang TC，後續候選 Noto Sans TC | PingFang TC，後續候選 Noto Sans TC |
| 排版特徵 | 宋體與無襯線配對，輕字重 | 全無襯線，柔和但清楚 | 無襯線標題較重，英文刊頭襯線對比 |
| 控制項／題卡圓角 | 4／8px | 12／16px | 2／0px |
| 密度／層級 | 中等，以字體與細線劃分 | 中等，以少量填色分組 | 較緊湊，以較強規則線與字重分層 |
| 圖示方向 | 1.5px 細線 | 1.75px、圓端點 | 1.5px、方正端點 |
| 桌面填答 | 單欄閱讀中心 | 單欄對話中心 | 暱稱與題卡左右配置，小螢幕回單欄 |
| 適合的原因 | 強調個人聲音、關係與生活質感 | 親切直覺，適合普遍日常使用 | 矩陣與回訪容易掃讀，資訊效率較高 |
| 主要缺點 | 宋體跨平台成本，可能顯得嚴肅 | 容易接近常見生活工具，品牌綠與 Yes 要分離 | 較理性，需避免像研究報告／後台 |

所有方向都不使用漸層、玻璃、裝飾插畫、大量陰影或無意義動畫。圓角與填色是各方向的具體取捨，並非完全禁止。

原型共用內容來源：`docs/tech-architecture/backend.md` 中的標題、描述、三個旅行題目與 Alice 示例答案；Bob／Carol 是用來展示差異的示範資料。日期是當日示範日期。沒有讀取正式資料，也沒有執行文件中的 seed。

## 6. 使用原型

從 repo 根目錄啟動：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory design/phase-1-2
```

用 Arc 打開 `http://127.0.0.1:4173/`。頂部可選 A／B／C 或並排比較，切換入口／建立／填答／結果，以及桌面／390／320px 內容寬度。窄瀏覽器會把三方向上下排列，避免擠小文字。

示範互動：搜尋名稱、編輯建立內容、新增問題（最多 20 題）、示範建立、暱稱、Yes／No／看狀況、上一題、必填、示範提交、結果矩陣、複製原型連結。各方向共用同一份暫存狀態；重新整理即重設。登入只說明正式功能，不開啟真實認證。

也可直接開啟 `index.html`；此情況瀏覽器可能限制剪貼簿，因此建議透過本機 server。原型沒有外部字型或圖示下載；系統字型 fallback 會影響非 Mac 的宋體呈現。

## 7. 驗證與限制

- 使用 Node 24.21.0、pnpm 10.13.1 啟動既有 Next.js；以命令列覆寫資料庫為 loopback 離線占位與停用帳號歷史，未讀寫正式 DB、未跑 migration／seed。
- Arc 實際查看既有首頁的資料不可用狀態、重複導覽，以及建立頁的提示、輸入框與題目列表。正式填答、結果、登入和帳號歷史以程式碼盤點；資料庫依賴流程未實測。
- 原型於 Arc 實際查看三方向入口、建立、填答與結果；操作 Yes → No → Depends、輸入「小明」、示範提交，確認三方向同步並顯示第 4 位參與者。另查看 320px 結果頁的內容寬度預覽。
- 在結果比較發現 Depends 欄位過窄，已改為依人數增加表格最小寬度，保留局部橫向捲動。
- JavaScript 經 Node 語法檢查。這不是正式產品測試；沒有新增自動化測試或把 lint／typecheck／build 稱作測試。
- 原型基本色組按相對亮度公式計算：A／B／C 的正文對背景為 13.43／12.13／13.31，輔助文字為 5.49／6.13／5.70，白字主按鈕為 6.60／6.91／8.13。只覆蓋這些實色配對，不能代表完整無障礙合規。
- 390／320 控制是桌面 Arc 中的內容寬度預覽，不代表 iPhone Safari 驗證。原型尚未部署到 Preview，不能以手機存取本機 loopback。
- 此階段不是完整 WCAG 審核，也不是所有元件／狀態的完整設計系統；顏色與字級是方向探索值。選定後再做全套 tokens、狀態、對比與元件規範。

下一個決策：選擇 A、B、C，或指出要保留哪些具體視覺特徵。收到方向確認前，不開始 Phase 3 品牌識別或 Phase 4 正式 Design System。

## B2 修正版（依使用者回饋）

使用者偏好 B，但希望色彩更鮮明、字體更有個性，首頁資訊更少且主 CTA 清楚。新增 `b2` 作為 B 的延伸，保留 B 原版與 `b-compare` 前後比較；不開始品牌識別或正式產品實作。

- 五種用途色：鈷藍 #3258CF 主 CTA、綠 #257052 Yes、珊瑚 #AC4032 No、琥珀 #8A6214 Depends、紫 #7056AB 次要導覽。暖白 #FFFDF7／深墨 #292C35 作閱讀基底。五色並非五個同等重要的品牌主色，也不表示每頁都要用滿五色。
- 首頁只留短標題「先說說你的想法。」、一行產品說明、主 CTA「新增表單」與次要文字入口。移除兩張解釋入口的卡片；既有表單保留搜尋、填寫和結果，以精簡列呈現。修改文案與呈現密度，沒有增加產品功能。
- 字體試用 Songti TC／Noto Serif TC 標題與題目、系統無襯線內文，以及 Georgia 斜體英文刊頭。此為排版探索，沒有設計或定案 Logo；系統字型跨平台呈現仍需後續確認。
- 延伸色彩到既有建立、填答與結果畫面，三種回答保留文字＋圖示＋色彩，避免只靠色相辨認。
- Arc 實際查看 B2 桌面首頁、填答題卡與三色回答按鈕、320px 首頁內容預覽。尚未實測 iPhone Safari。JavaScript 經 Node 語法檢查；只改隔離原型，因此未重跑正式 Next.js lint／typecheck／build。
- CTA 白字對藍色 6.12、Yes 文字對淺綠 5.12、Depends 對淺黃 4.77、紫色對暖白 5.72。No 的初稿色對淺珊瑚低於 4.5，已加深為 #AC4032，並重新計算；這些數值只涵蓋指定色組，不等於完整無障礙審核。

取捨：五色提高辨識與活潑感，但要由功能分工控制密度。宋體增加編輯感，也會帶來字型載入與跨平台一致性成本。首頁文案是可繼續調整的頁面文案，不是新品牌標語。預設開啟 B2 首頁，待使用者確認後再延伸。

## B3 修正版（更飽和、更有趣）

使用者認可 B2 的方向，但希望調整字體、提高飽和度，不必偏文青。新增 `b3`，保留 B2 與 `b-revision` 並排比較；預設改為 B3 首頁。

- 移除宋體標題與斜體刊頭，使用 Avenir Next／PingFang TC 無襯線組合。標題與題目提高字重，內文維持正常字重，透過大小與字重建立層級。這仍是字體候選，非定案字體或 Logo；其他平台使用 Noto Sans TC／sans-serif fallback。
- 五色提高飽和度：電光藍 #2948FF 主 CTA、鮮綠 #27CE7B Yes、珊瑚紅 #FF5C48 No、亮黃 #FFDC2E Depends、紫 #6835EF 題目／導覽。填答題卡改為實色紫搭白字，回答以亮色底搭深色文字。
- 保留 B2 精簡首頁、明確 CTA、既有內容與互動流程；趣味來自字重與功能配色，沒有增加功能、裝飾或動畫。
- Arc 實際查看 B3 桌面填答與 320px 首頁內容預覽，題卡、回答按鈕及首頁 CTA 未見重疊。此為桌面內容寬度預覽，尚未實測 iPhone Safari。
- JavaScript 經 Node 24.21.0 語法檢查。白字 CTA 對比 6.06、白字紫色題卡 6.28、Yes 6.14、No 4.97、Depends 8.72；數值只涵蓋這些指定色組，不代表完整無障礙審核。

取捨：B3 更直接、活潑，安靜感比 B2 少。所有修改維持在隔離原型，正式 Next.js 頁面未修改，未進入 Phase 3 或 Phase 4。

## 品牌 Icon 初步探索

使用者暫時接受 B3，接著詢問 icon 的設計方向。新增獨立 `icons.html`：三個 SVG 概念「各有形狀」「對話之間」「各自的節奏」，共用紫色 App 展示底，以及 48／32／16px 單色輪廓。優先建議探索「各有形狀」，以不同輪廓與間隔表達個體差異；概念仍待確認，沒有替換正式標誌或 favicon。

同頁展示 24px／2px 線寬／圓端點的功能圖示方向，以及 Yes／No／看狀況的圖示＋文字＋色彩。Arc 實際查看三個品牌草案、單色尺寸及下方功能圖示，未見重疊。這次沒有進行實際 favicon 整合、跨裝置驗證或完整設計系統實作。
